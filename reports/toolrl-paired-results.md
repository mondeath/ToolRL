# 固定开发集与新模板盲测：奖励对照

问题不是“把全部轨迹平均，工具成本能不能降”，而是“同一题两个模型都能做成时，加成本奖励能否让路径更省”。工具成本是按工具价目累加的单位，不是 GPU 费用，也不是调用次数。

## 协议

- Base 不训练。两个训练模型从同一 Qwen2.5-7B-Instruct 底座分别做 LoRA GRPO，训练种子 2026，240 组 × 4 条采样，取各自第 240 组的模型。Success-only 使用二元成功标记 S；Cost-aware 使用 `S × (1 − 0.2 × clip(C / 40, 0, 1))`，失败仍给 0。
- 固定 400 题 dev 用于开发；在开盲前冻结两个 checkpoint、提示、成本系数和评测协议。三个模型在相同的 72 题上贪心解码，每题每模型一次，未完成或答错仍计入分母。
- 环境迭代与奖励对照分开：旧环境的历史分数不作为此次奖励对照的基线。此次没有为 Cost-aware 改工具、改价或放宽成功条件。

## 三模型完整分母

| 数据集 | 模型 | 成功数 / 题数 | 工具成本总和 | 全题平均成本 |
|---|---|---:|---:|---:|
| dev | Base | 246/400 | 3554 | 8.885 |
| dev | Success-only | 399/400 | 2238 | 5.595 |
| dev | Cost-aware | 400/400 | 2100 | 5.250 |
| 盲测 | Base | 22/72 | 494 | 6.861 |
| 盲测 | Success-only | 35/72 | 331 | 4.597 |
| 盲测 | Cost-aware | 35/72 | 327 | 4.542 |

## 两个训练模型逐题配对后再分组

下表按任务 ID 对齐，列出所有非空组。两列成本都是**组内总和**，除以该行题数才是均值。

| 数据集 | Success-only / Cost-aware 是否成功 | 题数 | Success-only 成本 | Cost-aware 成本 |
|---|---|---:|---:|---:|
| dev | 是 / 是 | 399 | 2236 | 2099 |
| dev | 否 / 是 | 1 | 2 | 1 |
| 盲测 | 是 / 是 | 35 | 103 | 119 |
| 盲测 | 否 / 否 | 37 | 228 | 208 |

开发集共同成功题均差（Cost-aware 减 Success-only）为 `(2099 − 2236) / 399 = −0.343`；盲测变为 `(119 − 103) / 35 = +0.457`。两个模型盲测上没有一道题出现一方成功、另一方失败。37 道共同失败题节省的 20 个单位，抵消了共同成功题多花的 16 个单位；这解释了为何全题均值会给出相反方向。

## 证据与边界

以上汇总来自同题配对的逐题记录；发布分组计数与成本和，供读者无需 GPU 复算，不附原题、运行主机、原始轨迹或权重。对照记录的 SHA-256：开发集配对报告 `9346b870b4e6922b65feb9d89abbcb080a150382196f93f77c3d8d31f83da1ab`；三模型盲测报告 `a2067c7d75374576eb0f317c318ebbb4a4f2488849732501696044db6d2581ce`。

这是一组单训练种子的描述性结果。72 道题来自六个共享世界，不能视为 72 次独立训练重复；不能据此宣称成本奖励普遍有效或普遍有害，也不能再用这批盲测题调参后作为独立测试。
